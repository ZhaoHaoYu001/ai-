# FluentLoop 架构与关键决策

## 设计目标

1. 首次体验无需注册、无需 API Key。
2. 对话、评分、纠错和报告形成完整学习闭环。
3. 语音能力不可用时，文字输入能够无损降级。
4. MVP 的每个模块都能替换为生产级 AI 服务。

## 模块边界

- `src/data.js`：管理场景内容与纠错规则，便于内容运营扩展。
- `src/coach.js`：纯函数形式的分析与对话策略，可独立测试，也可替换为服务端 API。
- `src/ai-coach.js`：浏览器端 AI Coach 客户端，负责请求服务端并在失败时明确降级。
- `ai-service.js`：服务端模型适配器，使用结构化输出生成角色回复和语境化纠错。
- `server.js`：静态服务与受保护的 `/api/coach` 接口，避免向浏览器暴露 API Key。
- `src/app.js`：只负责状态、页面渲染、语音能力和用户交互。
- `src/styles.css`：统一视觉语言与响应式布局。

## 端到端语音链路

1. 用户点击“按下说话”。
2. 浏览器将英语语音实时转写为文本。
3. 回答完成后分析引擎同时计算四维评分和纠错建议。
4. Coach 根据场景与当前轮次生成自然追问。
5. Speech Synthesis 播放 Coach 回答，进入下一轮。

这种设计把反馈放在表达结束后，避免中途打断。当前语音链路省去服务器中转，降低 MVP 延迟；生产版本可用流式 STT、LLM 和 TTS 替换对应环节。

## 生产化建议

- 前端：React / TypeScript，状态机管理实时对话状态。
- 实时通道：WebSocket 或 WebRTC。
- AI 编排：LLM structured output，分离角色回答与教学反馈。
- 语音：流式 STT + 低延迟 TTS + 音素级发音评测。
- 数据：保存会话、句级评分与能力趋势，支持个性化复练。
- 安全：音频默认不永久保存，明确告知数据用途并支持删除。
